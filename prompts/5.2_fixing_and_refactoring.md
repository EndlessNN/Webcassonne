# 5.2 Виправлення помилок і узгодження

Реальні проблеми, які виникли під час реалізації US-01–US-04, і промпти, якими їх виправляли.

## 1. `gofmt -l` показує файли, які ніхто не змінював

Симптом: `gofmt -l server` виводить `errors.go`, `router.go`, `model.go`, `memory.go`, хоча їх не редагували. Причина — Git на Windows (`core.autocrlf=true`) підставляє CRLF при checkout, а gofmt вимагає LF.

```text
gofmt -l server показує файли, яких я не змінював (вивід нижче). git config core.autocrlf = true.
Знайди причину і виправ так, щоб це не повторювалося в інших членів команди на Windows.
Не вимикай перевірку gofmt і не роби масового переформатування без пояснення.
```

Результат: `.gitattributes` з `*.go text eol=lf` (і `go.mod`, `go.sum`), потім `gofmt -w`.

## 2. Гравець вилітає з лобі одразу після створення кімнати в dev-режимі

Проблему знайшли під час розбору плану, до запуску: React StrictMode у dev двічі монтує ефект. Перший WebSocket закривається, сервер вважає це виходом з лобі й видаляє гравця, а друге підключення отримує `INVALID_TOKEN`. Після виправлення перевірили в `npm run dev`: через 4 с гравець лишається в лобі.

```text
У dev-режимі (React StrictMode) Lobby відкриває WebSocket двічі: перше з'єднання одразу закривається,
і сервер прибирає гравця з лобі. Виправ на сервері, а не вимкненням StrictMode:
- AC US-04 дозволяє зникнення гравця за ≤ 5 с, тож можна чекати повторного підключення;
- закриття старої вкладки не повинно викидати гравця, якщо він уже підключився з нової;
- у тестах затримка має бути вимикана, щоб тести не спали.
Додай тест на сценарій «стара підписка закрилась після нової».
```

Результат: `Service.LeaveGrace` (2 с, у тестах 0), перевірка «чи ця підписка ще поточна» в `Disconnect`, тест `TestReconnect_OldSubDisconnectDoesNotKickPlayer`.

## 3. Сервер не стартує: порт 8080 зайнятий

```text
go run ./cmd/server падає, а на localhost:8080 відповідає Apache Tomcat з іншого курсу.
Зміни порт за замовчуванням так, щоб демо стартувало з чистого терміналу, і онови всі місця, де він згадується
(vite proxy, README, AGENTS.md, ADR). Порт має лишатися налаштовуваним через PORT.
```

Результат: порт 8090 (зроблено ще в каркасі, тут перевірено, що проксі Vite і WebSocket працюють через нього).

## 4. `go test -race` не запускається

```text
go test -race ./... на Windows падає з "-race requires cgo". Чи можна це обійти без встановлення gcc?
Якщо ні — зафіксуй в AGENTS.md, як запускати тести, і не прибирай вимогу потокобезпеки з коду.
```

Результат: на Windows тести запускаються без `-race`; конкурентний доступ захищено м'ютексом `room.Service`, а наскрізний WebSocket-тест перевіряє реальні горутини.

## 5. Типи клієнта розійшлися з контрактом

```text
Перевір, що web/src/api/types.ts збігається з docs/api.md поле в поле для всього, що використовують US-01–US-04
(createRoom, preview, join, room_state, error). Знайди розбіжності в назвах, nullable-полях і union-типах повідомлень.
Не додавай полів, яких немає в контракті; для game, що з'явиться в US-05, лиши null з коментарем shortcut.
Потім npm run build і npm run lint.
```

Результат: `color: Color | null`, `seat: number | null` (у лобі сервер віддає `null`), `ServerMessage` — union з `room_state` і `error`.

## Принципи, які ми тримали в промптах виправлень

| Принцип | Навіщо |
|---|---|
| Давати моделі точний вивід терміналу | Без нього модель гадає причину |
| Просити причину, а не лише фікс | Інакше модель вимикає перевірку (`gofmt`, StrictMode, `-race`) замість виправлення |
| Забороняти «зручні» обхідні шляхи явно | «Не вимикай StrictMode», «не прибирай перевірку» |
| Вимагати тест на виправлений баг | Баг не повертається непомітно |
