# 5.1 Генерація коду сценарію «Зібрати компанію в лобі» (US-01–US-04)

Інструмент: Claude Code (CLI-агент) у репозиторії. Агент автоматично читає `CLAUDE.md` → `AGENTS.md`, тому правила, стек і заборони в промпті не повторюються, лише посилання на них.

## Промпт 1. План перед кодом

```text
Ми реалізуємо перший наскрізний сценарій: US-01, US-02, US-03, US-04 з docs/requirements.md
(створити кімнату → скопіювати посилання → увійти за посиланням → живий список гравців у лобі).

Перед кодом:
1. Прочитай AGENTS.md, docs/api.md, docs/data-model.md, docs/technical-analysis.md (П-1, П-2, П-8) і Gherkin-сценарії US-01–US-04.
2. Склади список файлів, які створиш або зміниш, по шарах: store → room → httpapi → web/src/api → web/src/pages.
3. Випиши, які Gherkin-сценарії покриєш Go-тестами, а які перевіряються лише вручну в браузері.
4. Назви місця, де контракт неоднозначний або не покриває потрібну поведінку. Не вигадуй поля й коди помилок — спитай.

Не пиши код, поки я не підтверджу план.
```

## Промпт 2. Сервер

```text
План підтверджено. Реалізуй серверну частину US-01–US-04.

- Створи гілку feature/lobby-us01-us04.
- internal/store: методи Get, Add (false, якщо код зайнятий), Delete.
- internal/room: Service з Create, Preview, Join, Connect, Disconnect.
  - Валідація нікнейму: trim, 1–20 символів у рунах, унікальність у кімнаті без урахування регістру.
  - Код кімнати — 6 символів з алфавіту П-2; токен — 128 біт hex; playerId — UUID v4. Лише crypto/rand.
  - Помилки — тип room.Error з кодами й текстами з docs/api.md §1 і Gherkin-сценаріїв.
  - Знімки для WebSocket: канал з буфером 1, де завжди лежить найсвіжіший знімок, щоб повільний клієнт не блокував інших.
  - Вихід з лобі при закритті WebSocket, передача ролі організатора (П-8), видалення порожньої кімнати.
- internal/httpapi: POST /api/rooms, GET /api/rooms/{code}, POST /api/rooms/{code}/players,
  GET /api/rooms/{code}/ws?token=… (github.com/coder/websocket). Помилки до апгрейду — звичайним REST у єдиному форматі.
  room_state — рівно поля з docs/api.md; color і seat у лобі — null; game — null.
- cmd/server: посилання /r/{code} віддає index.html.

Тести першими: табличні тести room.Service за кожним Gherkin-сценарієм US-01, US-03, US-04
і наскрізний тест через httptest + websocket.Dial (вхід другого гравця і вихід — у знімку першого).
Після коду запусти go vet, go test, gofmt -l і покажи результат.
```

## Промпт 3. Клієнт

```text
Тепер клієнт для того ж сценарію, без нових залежностей (жодного react-router).

- web/src/api/types.ts: типи відповідей і room_state рівно з docs/api.md. GameView поки не додавай — поле game: null з коментарем shortcut.
- web/src/api/client.ts: request<T> з помилкою RequestError(code, message), createRoom, getRoomPreview, joinRoom, openRoomSocket.
- Екрани: Home (форма нікнейму, US-01), Invite для /r/{code} (спершу preview: не знайдено / заповнена / почалася, потім форма, US-03),
  Lobby (кнопка «Скопіювати посилання» з «Скопійовано» на 2 с і запасним полем для ручного копіювання, живий список,
  позначки «організатор» і «(ви)», US-02 і US-04).
- Спільна форма NicknameForm показує повідомлення сервера під полем (role="alert"). Клієнт нікнейм сам не валідує — джерело правди сервер.
- Токен — лише в стані React (ADR-0005), не в localStorage.

Після коду: npm run build, npm run lint. Потім підніми сервер і пройди сценарій у браузері двома вкладками, включно з помилкою зайнятого нікнейму.
```

## Що закладено в промпти і чому

| Елемент | Навіщо |
|---|---|
| Окремий крок «план без коду» | Агент спершу знаходить прогалини в контракті, а не вигадує поля мовчки |
| Поділ на сервер → клієнт → документація | Кожен крок малий і перевіряється окремо; контекст моделі не переповнюється |
| Посилання на AGENTS.md замість повторення правил | Правила в одному місці; промпт коротший |
| Конкретні рішення в промпті (буфер 1, crypto/rand, null у лобі) | Без них модель обирає небезпечні дефолти (math/rand для токенів, блокуючу розсилку) |
| «Тести першими» за Gherkin | Тест = критерій приймання; модель не підганяє тест під код |
| Живий прогін у браузері двома вкладками | Типи й тести не ловлять проблем WebSocket і StrictMode |
