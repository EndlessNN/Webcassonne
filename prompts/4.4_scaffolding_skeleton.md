# 4.4 Каркас застосунку (Walking Skeleton) та інструкції для ШІ

## Фінальна версія промпту

```text
Дій як Senior Full-Stack Engineer, який піднімає «крокуючий скелет» (Walking Skeleton): найменший наскрізний каркас, що збирається, запускається і з'єднує всі шари, але не містить жодної бізнес-логіки.

Проєкт: «Webcassonne». Рішення й контракти:
<контекст>
[вставити ADR-0001…0005 з docs/adr/, docs/data-model.md, docs/api.md]
</контекст>

Середовище: Windows 11, Go 1.26, Node 24. Порт 8080 зайнятий іншим проєктом.

Частина 1 — каркас:
1. Структура: `server/` (Go-модуль) і `web/` (Vite, шаблон react-ts) у корені репозиторію.
2. Сервер:
   - `GET /api/health` → 200 і JSON з `docs/api.md` (статус + тип сховища + кількість кімнат);
   - будь-який інший `/api/*` → 404 у єдиному форматі помилки (щоб формат було видно наживо);
   - сховище в пам'яті (`internal/store`) з одним методом, який використовує health;
   - структури з `docs/data-model.md` у `internal/model` — лише поля, без методів;
   - роздача зібраного `web/dist`, якщо він є; порт і шлях до UI — зі змінних середовища зі значеннями за замовчуванням;
   - один тест на health і один на формат 404.
3. Клієнт:
   - сторінка-заглушка українською: назва проєкту, стан зв'язку з сервером (результат `/api/health`), список майбутніх екранів з номерами історій;
   - `src/api/types.ts` з типами health і помилки рівно як у `docs/api.md`;
   - проксі `/api` (з WebSocket) на Go-сервер у dev-режимі;
   - прибрати демо-вміст шаблону Vite.
4. Запуск з чистого терміналу двома командами з кореня, без `cd`.
5. Без залежностей поза стандартною бібліотекою Go і шаблоном Vite. Бібліотеку WebSocket не додавати, поки її не потребує перша історія.

Частина 2 — інструкції для ШІ (`AGENTS.md`, а `CLAUDE.md` і `GEMINI.md` містять лише `@AGENTS.md`), українською:
- суть проєкту і поточний стан;
- таблиця джерел правди в `docs/`;
- стек, структура папок (наявні й майбутні пакети), напрямок залежностей між шарами;
- точні команди запуску, dev-режиму, тестів, лінтерів — лише ті, що реально працюють;
- правила кодогенерації: глосарій «українською → у коді», прив'язка до US-XX, тест першим для підрахунку очок, сервер — джерело правди;
- інженерні заборони: не вигадувати поля, коди помилок, правила гри й склад тайлів; не змінювати тести під код; не виходити за межі MVP; не додавати залежності; не комітити без прохання;
- Definition of Done для історії.

Після генерації запусти збірку, тести й лінтер, підніми сервер і перевір `/api/health` і сторінку в браузері. Повідом, що реально перевірено.
```

## Що закладено в промпт і чому

| Елемент промпту | Навіщо |
|---|---|
| Явне «без бізнес-логіки» і перелік того, що саме має бути | Головна пастка етапу: ШІ одразу починає писати кімнати й ходи |
| Контракти й ADR як вхід | Каркас має збігатися з документами: шляхи, формат помилки, пакети |
| 404 у єдиному форматі помилки | Дешевий спосіб показати контракт помилок наживо на демо |
| `internal/model` лише з полями | Рівень спільних моделей є, а логіки немає |
| Середовище і зайнятий порт 8080 | На ноутбуці команди 8080 зайнятий Tomcat з курсу Spring; без цього демо падає на старті |
| Дві команди з кореня, `go -C`, `npm --prefix` | Вимога курсу «1–2 команди з чистого терміналу» |
| Заборона зайвих залежностей і WebSocket «на потім» | Каркас лишається мінімальним; бібліотека з'являється разом з історією |
| `AGENTS.md` як єдине джерело, `CLAUDE.md`/`GEMINI.md` імпортують | У команді різні ШІ-інструменти, правила не дублюються |
| «Лише команди, що реально працюють» і фінальна перевірка | ШІ схильний документувати неіснуючі скрипти (`npm test` без тестів) |
