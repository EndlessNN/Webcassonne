# 3.3 Карта історій і розділення на MVP та Post-MVP

## Фінальна версія промпту

```text
Дій як досвідчений Agile-коуч, який допомагає студентській команді провести жорстку лінію відсікання MVP методом User Story Mapping (Jeff Patton).

Контекст: команда з 3 розробників, один семестр (~12 тижнів розробки), без бюджету. Продукт «Webcassonne» — браузерна емуляція базової гри «Carcassonne» (72 тайли, 2–5 гравців, по 7 міплів) з мультиплеєром і автоматичним підрахунком очок. Наприкінці курсу команда наживо демонструє одну повну партію кількох гравців від створення кімнати до фінального рахунку.

Рішення команди щодо меж (обов'язкові):
- IN: вхід гостем без реєстрації; повний автоматичний підрахунок, включно з полями; підказки правил для новачка (підсвітка допустимих позицій, коротка довідка).
- OUT: відновлення партії після відключення гравця (свідомо відкладаємо через складність збереження стану).
- WON'T: рейтинг, матчмейкінг з випадковими суперниками, турніри (це анти-персона «Змагальний гравець»).

[вставити 6 кроків з 3.1]
</шлях користувача>

<драфти історій>
[вставити повний список драфтів з 3.2]

Завдання:
1. Побудуй карту історій: кроки шляху — це «хребет» (activities), під кожним кроком згрупуй драфти. Об'єднай дублікати та переформулюй надто розмиті драфти.
2. Проведи лінію відсікання MVP. В In Scope лишається лише мінімальний наскрізний набір: без нього неможливо зіграти одну повну чесну партію з автоматичним підрахунком або він прямо закриває рішення команди вище.
3. Для кожної історії в Out of Scope коротко вкажи причину відкладення (складність, не потрібна для демо, обслуговує вторинну персону тощо).
4. Перевір, що в MVP немає «дірок»: кожен крок шляху має хоча б одну історію In Scope, і партію можна пройти від початку до кінця.
5. Перевір реалістичність: оціни кожну MVP-історію розміром S/M/L і скажи, чи вкладається сума в семестр для 3 людей. Якщо ні — запропонуй, що ще вирізати.

Формат: українською, markdown. Для кожного кроку — таблиця з колонками «Історія | Скоуп (MVP / Post-MVP / Won't) | Розмір або причина відкладення». Наприкінці — список ризиків, які створює відрізаний скоуп.
```

## Що закладено в промпт і чому

| Елемент промпту | Навіщо |
|---|---|
| Обмеження команди і формат фінального демо | Лінія відсікання має сенс тільки відносно реальних сил і того, що ми покажемо наживо |
| Обов'язкові IN/OUT/WON'T рішення команди | Ці рішення ухвалила команда, а не ШІ. Модель має працювати в цих межах, а не переглядати їх |
| Критерій «одна повна чесна партія» | Об'єктивне правило відсікання замість «важливо/неважливо» |
| Причина для кожної відкладеної історії | Команда розуміє, від чого свідомо відмовилася, і може пояснити це на захисті |
| Перевірка на «дірки» та оцінка S/M/L | MVP має бути наскрізним і вміщатися в семестр |
| Список ризиків відрізаного скоупу | Наприклад, без відновлення після відключення партія зупиниться, якщо хтось вийде. Це треба знати заздалегідь |
