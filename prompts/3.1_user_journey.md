# 3.1 Моделювання шляху користувача (User Journey)

## Фінальна версія промпту

```text
Дій як Senior Product Manager, який проєктує онлайн-версії настільних ігор для невеликих знайомих компаній.

Я розробляю вебзастосунок «Webcassonne»: сайт, що емулює фізичну копію настільної гри «Carcassonne» (базова гра без доповнень) з мультиплеєром у браузері та автоматичним підрахунком очок. Команда з 3 людей, строк — один семестр.

<основна персона>
«Організатор віддаленого вечора», 21–30 років [гіпотеза]. Збирає друзів, які розʼїхалися по різних містах, на регулярну партію онлайн, зазвичай під голосовий дзвінок у Discord. Правила Carcassonne знає. Зараз грає через фізичну копію і камеру над столом, а очки рахує вручну.
Болі: перші 20 хвилин йдуть на налаштування; хтось із друзів не може зайти через реєстрацію; ручний підрахунок полів довгий і викликає суперечки.
Вторинна персона: «Допитливий новачок», який не знає правил і боїться зіпсувати гру іншим.
</основна персона>

<рішення, які вже ухвалила команда>
- Вхід гостем: лише нікнейм, без реєстрації.
- Кімната створюється в один крок, друзі заходять за посиланням.
- Повний автоматичний підрахунок очок, включно з полями наприкінці гри.
- Для новачка: підсвітка допустимих позицій тайла і коротка довідка з правил.
</рішення, які вже ухвалила команда>

Завдання: опиши головний шлях основної персони за успішним сценарієм (Happy Path) — від першого відкриття сайту до моменту, коли компанія бачить фінальний результат партії.

Вимоги:
1. 4–6 послідовних кроків. Шлях лінійний: без розгалужень, помилок і альтернативних сценаріїв.
2. Для кожного кроку: назва (дієслово + об'єкт), що робить користувач, що показує або робить система, що користувач отримує в результаті, і який біль персони цей крок закриває.
3. Кроки мають відповідати реальній логіці партії Carcassonne: хід = витягнути тайл → покласти → за бажанням поставити міпла → підрахунок завершених об'єктів.
4. Крок, у якому гравці повторюють дію багато разів (ходи), познач як цикл, але опиши один раз.
5. Не додавай функцій, яких немає в описі (акаунти, рейтинг, чат, боти).

Формат: українською, markdown, нумерований список кроків, у кожному кроці — короткі пункти без довгих абзаців. Наприкінці — один рядок зі схемою шляху через стрілки.
```

## Що закладено в промпт і чому

| Елемент промпту | Навіщо |
|---|---|
| Персона з README з болями та вторинна персона | Без конкретної людини ШІ описує абстрактного «користувача», і кроки не прив'язані до болів |
| Рішення, які команда вже ухвалила | Шлях має відображати наш продукт, а не загальне уявлення про онлайн-ігри |
| Лише Happy Path, 4–6 кроків, лінійно | Помилки й гілки розглядаємо пізніше в критеріях приймання; тут потрібен хребет карти історій |
| Логіка ходу Carcassonne | Модель інколи пропускає розміщення міпла або плутає момент підрахунку |
| Цикл ходів описується один раз | Інакше шлях роздувається повторюваними кроками |
| Заборона вигадувати функції | Щоб у шлях не потрапили акаунти та рейтинг, які ми свідомо не робимо |
