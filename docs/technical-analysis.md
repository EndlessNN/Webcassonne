## 1. Ключові сутності

| Сутність | Що це | Історії |
|---|---|---|
| **Room** (кімната) | Контейнер однієї партії: код для посилання, організатор, гравці, статус | US-01…US-05 |
| **Player** (гравець) | Гість з нікнеймом у межах однієї кімнати. Акаунта немає | US-01, US-03, US-04 |
| **Game** (партія) | Стан гри всередині кімнати: стопка, поле, черга ходу, фаза | US-05…US-16 |
| **TileType** (тип тайла) | Статичний каталог базової гри: сторони, сегменти об'єктів, щити, монастир | US-09…US-12 |
| **PlacedTile** (покладений тайл) | Тайл на полі: координати, тип, обертання | US-06, US-12 |
| **Meeple** (міпл) | Фішка гравця на сегменті покладеного тайла | US-13, US-16, US-19 |
| **Feature** (об'єкт) | Дорога, місто, монастир або поле, зібрані з сегментів кількох тайлів. **Обчислюється**, не зберігається | US-13, US-18, US-21, US-22 |
| **ScoreEntry** (нарахування) | Один запис «гравець, категорія, очки, хід». Рахунок = сума записів | US-18, US-20…US-23 |

## 2. Життєві цикли

### Room

```text
            start_game (організатор, 2–5 гравців)          останній тайл зіграно
  LOBBY ───────────────────────────────────────▶ PLAYING ─────────────────────────▶ FINISHED
    │                                               │
    │ усі вийшли                                    │ гравець відключився
    ▼                                               ▼
 (видалена)                                     ABANDONED
```

- `LOBBY`: можна приєднатися (до 5 гравців) і вийти. Вихід = закриття вкладки (WebSocket закрито).
- `PLAYING`: приєднатися не можна. Відключення будь-якого гравця → `ABANDONED`. Відновлення немає (рішення MVP).
- `FINISHED`, `ABANDONED`: кінцеві стани, змін немає. Кімната живе в пам'яті до перезапуску сервера або очищення (див. припущення П-7).

### Хід (фаза Game)

```text
 ┌───────────────────────────────────────────────────────────────────────────┐
 ▼                                                                           │
DRAW (сервер, автоматично) ──▶ PLACE_TILE ──place_tile──▶ PLACE_MEEPLE ──place_meeple / skip_meeple──▶ SCORE (сервер) ──┘
 │  тайл не можна покласти → скинути, тягнути ще                                  наступний гравець
 │  стопка порожня → фінальний підрахунок → Room FINISHED
```

- `DRAW` і `SCORE` — миттєві кроки сервера, не очікують гравця. Клієнт бачить лише `PLACE_TILE` і `PLACE_MEEPLE`.
- Обертання тайла (US-10) — локальна дія клієнта. Сервер отримує остаточне обертання разом з `place_tile`.

### Meeple

```text
SUPPLY ──place_meeple──▶ ON_BOARD ──об'єкт завершено (дорога/місто/монастир)──▶ SUPPLY
                            │
                            └── поле або незавершений об'єкт: лишається до кінця партії
```

### Player

```text
JOINED (лобі) ──start_game──▶ PLAYING (колір, місце в черзі) ──кінець партії──▶ FINISHED
   │                              │
   └─вийшов → видалений           └─відключився → кімната ABANDONED
```

## 3. Бізнес-правила й заборони

Система **ніколи не повинна**:

1. Створювати кімнату або гравця з нікнеймом поза 1–20 символами (після обрізання пробілів) або з нікнеймом, уже зайнятим у цій кімнаті (без урахування регістру).
2. Пускати в кімнату шостого гравця або будь-кого після старту партії.
3. Починати партію з менш ніж 2 гравцями або за командою не організатора.
4. Приймати дію гравця не в його хід або не в тій фазі.
5. Класти тайл на зайняту клітинку, на клітинку без сусідів або так, що хоча б одна суміжна сторона не збігається.
6. Залишати гравцю тайл, який неможливо покласти нікуди: такий тайл скидається, гравець тягне наступний.
7. Ставити міпла не на щойно покладений тайл, на об'єкт, де вже є міпл (з урахуванням з'єднаних тайлів), або коли в запасі 0 міплів.
8. Рахувати очки на клієнті або довіряти клієнту в стані гри. Сервер — єдине джерело правди.
9. Розкривати клієнтам порядок стопки або токени інших гравців.
10. Змінювати рахунок інакше, ніж записом `ScoreEntry`. Сума записів = рахунок, розбивка за категоріями (US-23) сходиться із загальною сумою.
11. Повертати міплів з полів до кінця партії.

Правила підрахунку — у [requirements.md §4](requirements.md#4-критерії-приймання-acceptance-criteria) (US-18, US-21, US-22). Еталон — фізична копія команди.

## 4. Технічні припущення MVP

| # | Припущення | Обґрунтування |
|---|---|---|
| П-1 | **Автентифікації немає.** Під час створення або входу в кімнату сервер видає гравцю випадковий `token` (128 біт, hex). Клієнт тримає його лише в пам'яті вкладки й передає при підключенні до WebSocket | Вхід гостем; оновлення сторінки не підтримується, тож зберігати токен не треба |
| П-2 | Код кімнати — 6 символів з алфавіту без схожих знаків (`ABCDEFGHJKLMNPQRSTUVWXYZ23456789`), напр. `K7QM2X`. Посилання: `/r/K7QM2X` | Легко продиктувати голосом; 32⁶ ≈ 10⁹ варіантів достатньо |
| П-3 | `playerId` — UUID v4 (рядок). Публічний, на відміну від `token` | Стандартний формат без БД |
| П-4 | Усі дії в лобі й партії йдуть через WebSocket. Після кожної зміни сервер розсилає **повний знімок** стану кімнати | Найпростіша синхронізація; стан малий (≤ 72 тайли) |
| П-5 | Стан — у пам'яті процесу. Перезапуск сервера видаляє всі кімнати | ADR-0004; відновлення поза MVP |
| П-6 | Координати поля — цілі `(x, y)`, стартовий тайл у `(0, 0)`, `y` росте вниз. Обертання — 0/90/180/270 за годинниковою стрілкою | Однаково для сервера й клієнта |
| П-7 | Кімнати в `FINISHED`/`ABANDONED` видаляються через 1 годину | Обмеження пам'яті без БД |
| П-8 | Якщо організатор виходить з лобі, організатором стає гравець, який приєднався найраніше | Інакше лобі «зависає» без кнопки старту |
| П-9 | Кольори призначаються на старті в порядку RED, BLUE, GREEN, YELLOW, BLACK за випадковим порядком ходу | US-05: колір автоматично, вибору немає |
| П-10 | Десктопні Chrome/Firefox/Edge останніх версій | Скоуп «десктопний браузер» |

## 5. Знайдені прогалини у вимогах

| # | Прогалина | Як закрили |
|---|---|---|
| G-1 | Немає каталогу 72 тайлів: без нього не реалізувати US-09…US-13 | Формат зафіксовано в [data-model.md](data-model.md#tiletype-статичний-каталог). Вміст `docs/tiles.md` команда звіряє з фізичною копією до US-09 |
| G-2 | Не сказано, що відбувається з партією, якщо гравець відключився | Кімната → `ABANDONED`, усім приходить знімок з цим статусом. UI показує «Партію перервано» |
| G-3 | Не сказано, хто стає організатором, якщо він вийшов з лобі | П-8 |
| G-4 | Невідомо, як довго живе кімната | П-7 |
| G-5 | US-11 (підсвітка) потребує, щоб клієнт знав допустимі позиції, але правила рахує лише сервер | Сервер надсилає `legalPlacements` для поточного тайла в усіх обертаннях |
| G-6 | US-13 не каже, як гравець обирає об'єкт на тайлі | Сервер надсилає `legalMeepleSegments`; клієнт показує їх як точки на тайлі |
| G-7 | US-02/US-03: формат посилання не визначено | П-2 |
| G-8 | Чи бачать інші гравці витягнутий тайл? | Так, як у фізичній грі: `currentTile` бачать усі |
