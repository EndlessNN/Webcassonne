# Webcassonne — специфікація вимог

> Персона: **«Організатор віддаленого вечора»** (див. [README](../README.md)). Він знає правила і пояснює їх друзям сам, тому продукт не навчає правилам.
> Скоуп: базова гра Carcassonne без доповнень (72 тайли, 2–5 гравців, по 7 міплів), десктопний браузер, вхід гостем за нікнеймом.
> Мережа: лише щасливий сценарій. Усі гравці мають стабільне з'єднання і не оновлюють сторінку.
> Промпти, з якими створювався документ: [`prompts/3.1`–`3.5`](../prompts/).

---

## 1. Головний шлях користувача (User Journey, Happy Path)

1. **Створити кімнату**
   - Користувач: відкриває сайт, вводить нікнейм, натискає «Створити кімнату».
   - Система: створює кімнату без реєстрації, робить користувача організатором і відкриває лобі.
   - Результат: кімната готова за кілька секунд.
   - Закриває біль: 20 хвилин налаштувань перед грою.
2. **Запросити друзів**
   - Користувач: копіює посилання-запрошення і кидає його в Discord/месенджер.
   - Система: друзі відкривають посилання, вводять нікнейм і з'являються в лобі в усіх у реальному часі.
   - Результат: уся компанія в одній кімнаті.
   - Закриває біль: «хтось не може зайти через реєстрацію».
3. **Почати партію**
   - Користувач: організатор натискає «Почати гру», коли зібралося 2–5 гравців.
   - Система: призначає кольори та випадковий порядок ходів, кладе стартовий тайл, роздає по 7 міплів.
   - Результат: у кожного на екрані той самий стіл, фізична копія не потрібна.
4. **Зіграти хід** *(цикл, повторюється до кінця стопки)*
   - Користувач: отримує тайл, обертає його, кладе на одну з підсвічених позицій, за бажанням ставить міпла.
   - Система: перевіряє правила стикування, показує хід усім гравцям.
   - Результат: гра йде за правилами без суперечок, ніхто не витрачає час на перевірку стикування.
5. **Отримати очки за завершені об'єкти**
   - Система: після кожного ходу автоматично нараховує очки за завершені дороги, міста й монастирі та повертає з них міплів. Селяни на полях залишаються до кінця партії.
   - Результат: рахунок завжди актуальний, ніхто не рахує вручну.
6. **Побачити фінальний результат**
   - Система: після останнього тайла рахує незавершені об'єкти й поля, показує таблицю з переможцем і розбивкою очок.
   - Результат: партія закінчена, переможець визначений без ручного підрахунку полів.

**Схема:** Створити кімнату → Запросити друзів → Почати партію → Зіграти хід (цикл) → Отримати очки → Побачити фінальний результат

## 2. Карта історій і межі скоупу

Позначки: **MVP** — у скоупі семестру, **Post** — свідомо відкладено, **Won't** — не робимо (поза фокусом продукту).
Розмір MVP-історій: S — до 2 днів, M — до тижня, L — більше тижня для однієї людини.

### Крок 1. Створити кімнату

| Історія | Скоуп | Розмір / причина відкладення |
|---|---|---|
| Створити кімнату, ввівши лише нікнейм | MVP (US-01) | S |
| Зареєструватися й увійти в акаунт | Post | Суперечить рішенню «вхід гостем»; не потрібно для демо |
| Налаштувати кімнату (доповнення, варіанти правил) | Post | Доповнення поза скоупом базової гри |
| Захистити кімнату паролем | Post | Посилання і так приватне |
| Переглянути історію своїх партій | Post | Потребує акаунтів |

### Крок 2. Запросити друзів

| Історія | Скоуп | Розмір / причина відкладення |
|---|---|---|
| Скопіювати посилання-запрошення в один клік | MVP (US-02) | S |
| Зайти в кімнату за посиланням, ввівши лише нікнейм | MVP (US-03) | S |
| Бачити список гравців у лобі в реальному часі | MVP (US-04) | M |
| Обрати колір міплів | Post | Колір призначається автоматично |
| Показати QR-код кімнати | Post | Посилання достатньо |
| Видалити гравця з лобі | Post | Знайома компанія, низький ризик |
| Вбудований голосовий/текстовий чат | Post | Персона вже сидить у Discord |
| Зайти глядачем | Post | Не потрібно для одної партії |

### Крок 3. Почати партію

| Історія | Скоуп | Розмір / причина відкладення |
|---|---|---|
| Запустити партію при 2–5 гравцях | MVP (US-05) | M |
| Додати бота замість відсутнього гравця | Post | Гра з ботом не входить у MVP; складний ШІ гравця |
| Знайти випадкових суперників (матчмейкінг) | Won't | Компанію збирає організатор |

### Крок 4. Зіграти хід

| Історія | Скоуп | Розмір / причина відкладення |
|---|---|---|
| Бачити ігрове поле з тайлами й міплами | MVP (US-06) | M |
| Бачити, чий зараз хід | MVP (US-07) | S |
| Переміщати (панорамувати) поле | MVP (US-08) | S |
| Отримати тайл зі стопки на початку ходу | MVP (US-09) | S |
| Обертати тайл | MVP (US-10) | S |
| Бачити підсвічені допустимі позиції тайла | MVP (US-11) | M |
| Покласти тайл на допустиму позицію | MVP (US-12) | L |
| Поставити міпла на вільний об'єкт | MVP (US-13) | L |
| Пропустити розміщення міпла | MVP (US-14) | S |
| Бачити ходи інших гравців без перезавантаження | MVP (US-15) | M |
| Бачити кількість своїх міплів і тайлів у стопці | MVP (US-16) | S |
| Масштабувати поле | Post | Для демо достатньо панорамування |
| Скасувати свій хід (undo) | Post | Ускладнює синхронізацію стану |
| Таймер ходу | Post | Знайома компанія, темп регулюється в дзвінку |
| Анімації й звуки | Post | Не впливає на можливість зіграти |
| Відкрити коротку довідку з правил під час партії (раніше US-17) | Post | Правила пояснює організатор; навчання не входить у MVP |
| Інтерактивний туторіал / гра з ботом для навчання | Post | Навчання не входить у MVP; великий обсяг |
| Мобільна версія інтерфейсу | Post | Демо на десктопі |

### Крок 5. Отримати очки

| Історія | Скоуп | Розмір / причина відкладення |
|---|---|---|
| Автоматично отримати очки за завершені дороги, міста й монастирі | MVP (US-18) | L |
| Автоматично повернути міплів з завершеного об'єкта | MVP (US-19) | S |
| Бачити поточний рахунок усіх гравців | MVP (US-20) | S |
| Бачити підсвітку об'єкта, за який нараховано очки | Post | Приємно, але не обов'язково |
| Журнал подій «хто, за що, скільки» | Post | Частково замінюється фінальною розбивкою |

### Крок 6. Побачити фінальний результат

| Історія | Скоуп | Розмір / причина відкладення |
|---|---|---|
| Отримати очки за незавершені об'єкти в кінці гри | MVP (US-21) | M |
| Отримати очки за поля в кінці гри | MVP (US-22) | L |
| Бачити фінальну таблицю з переможцем і розбивкою | MVP (US-23) | S |
| Зіграти реванш тією ж компанією | Post | Можна створити нову кімнату |
| Поділитися результатом | Post | Не потрібно для демо |
| Особиста статистика й рейтинг | Won't | Не потрібні для гри знайомою компанією; потребують акаунтів |

### Наскрізні історії

| Історія | Скоуп | Причина |
|---|---|---|
| Повернутися в ту саму партію після відключення або оновлення сторінки | Post | Рішення команди: MVP підтримує лише щасливий сценарій мережі |
| Інтерфейс англійською | Post | Перша спільнота — українські студенти |
| Доступність (клавіатура, контраст) | Post | Не критично для першого демо |

### Ризики відрізаного скоупу

- **Немає відновлення після відключення.** Якщо гравець під час партії закриє вкладку, оновить сторінку або втратить з'єднання, партію не вдасться продовжити, і її доведеться почати заново. Це прийняте обмеження MVP: окремої обробки цієї ситуації не робимо. Це перший кандидат після MVP.
- **Немає мобільної версії.** Друг з телефоном може не впоратися з інтерфейсом.
- **Обсяг ігрової логіки.** US-12, US-13, US-18, US-21 і US-22 (з'єднання об'єктів, підрахунок полів) — найбільші й найризикованіші. Логіка правил і підрахунку реалізується першою, як окремий модуль без залежності від інтерфейсу та мережі, і покривається модульними тестами за сценаріями з розділу 4 до інтеграції в інтерфейс.

## 3. Специфікація історій у роботі (MVP)

### Декомпозиція драфтів

| Драфт (було) | Стало | Що змінено |
|---|---|---|
| Як організатор, я хочу створити кімнату і запросити друзів | US-01, US-02 | Дві дії розділено |
| Як гравець, я хочу бачити поле і чий хід | US-06, US-07 | Два різні шматки стану розділено |
| Як гравець, я хочу переміщати й масштабувати поле | US-08 (+ масштаб у Post) | Розділено; масштаб відкладено |
| Як гравець, я хочу витягнути тайл, повернути і покласти його | US-09, US-10, US-12 | Три дії розділено |
| Як новачок, я хочу бачити, куди можна покласти тайл, і довідку з правил | US-11 (+ довідка в Post) | Розділено; довідку відкладено; «новачок» → «гравець» |
| Як гравець, я хочу поставити міпла або пропустити | US-13, US-14 | Дві альтернативні дії розділено |
| Як гравець, я хочу, щоб система рахувала всі очки | US-18, US-21, US-22 | Розділено за моментом гри та типом об'єкта |
| Як гравець, я хочу отримувати очки і міплів назад | US-18, US-19 | Розділено |
| Як користувач, я хочу бачити рахунок | US-20 | «Користувач» → «гравець», додано цінність |

### Фінальний список історій

**Крок 1. Створити кімнату**
- **US-01.** Як організатор, я хочу створити ігрову кімнату, ввівши лише нікнейм, щоб почати збирати компанію без реєстрації.

**Крок 2. Запросити друзів**
- **US-02.** Як організатор, я хочу скопіювати посилання-запрошення одним кліком, щоб швидко надіслати його друзям у Discord чи месенджер.
- **US-03.** Як запрошений друг, я хочу зайти в кімнату за посиланням, ввівши лише нікнейм, щоб приєднатися до гри без реєстрації.
- **US-04.** Як учасник лобі, я хочу бачити список гравців у кімнаті в реальному часі, щоб знати, хто вже зайшов і чи можна починати.

**Крок 3. Почати партію**
- **US-05.** Як організатор, я хочу запустити партію, коли в лобі 2–5 гравців, щоб уся компанія одночасно почала гру.

**Крок 4. Зіграти хід**
- **US-06.** Як гравець, я хочу бачити ігрове поле з усіма покладеними тайлами та міплами, щоб розуміти поточний стан партії.
- **US-07.** Як гравець, я хочу бачити, чий зараз хід, щоб знати, коли діяти мені.
- **US-08.** Як гравець, я хочу переміщати ігрове поле мишею, щоб бачити частини карти, які не вміщаються на екрані.
- **US-09.** Як гравець, я хочу на початку свого ходу отримати випадковий тайл зі стопки, щоб спланувати, куди його покласти.
- **US-10.** Як гравець, я хочу обертати свій тайл на 90°, щоб підібрати потрібну орієнтацію.
- **US-11.** Як гравець, я хочу бачити підсвічені допустимі позиції для свого тайла, щоб швидше ходити і не сперечатися про стикування.
- **US-12.** Як гравець, я хочу покласти тайл на допустиму позицію, щоб розширити карту.
- **US-13.** Як гравець, я хочу поставити міпла на вільний об'єкт щойно покладеного тайла, щоб претендувати на очки за цей об'єкт.
- **US-14.** Як гравець, я хочу пропустити розміщення міпла, щоб зберегти міплів для вигідніших ходів.
- **US-15.** Як гравець, я хочу бачити ходи інших гравців одразу після їх виконання, щоб стежити за грою без перезавантаження сторінки.
- **US-16.** Як гравець, я хочу бачити кількість своїх вільних міплів і тайлів у стопці, щоб планувати ходи до кінця партії.
- *US-17 відкладено (довідка з правил, див. карту історій).*

**Крок 5. Отримати очки**
- **US-18.** Як гравець, я хочу автоматично отримувати очки за завершені дороги, міста й монастирі, щоб не рахувати їх вручну і не сперечатися.
- **US-19.** Як гравець, я хочу автоматично отримувати назад міплів із завершеного об'єкта, щоб використати їх знову.
- **US-20.** Як гравець, я хочу бачити поточний рахунок усіх гравців, щоб розуміти, хто лідирує.

**Крок 6. Побачити фінальний результат**
- **US-21.** Як гравець, я хочу, щоб після останнього тайла автоматично нарахувалися очки за незавершені дороги, міста й монастирі, щоб фінальний рахунок був повним.
- **US-22.** Як гравець, я хочу, щоб у кінці гри автоматично нарахувалися очки за поля, щоб не витрачати час і не сперечатися за найскладніший підрахунок.
- **US-23.** Як гравець, я хочу бачити фінальну таблицю з переможцем і розбивкою очок за типами об'єктів, щоб усі погодилися з результатом.

## 4. Критерії приймання (Acceptance Criteria)

Сценарії US-13, US-18, US-19, US-21 і US-22 — основа модульних тестів модуля правил і підрахунку.

> ⚠️ **Перевірити за фізичною копією.** Значення очок відповідають актуальному виданню правил: завершене місто з 2 тайлів дає 4 очки, селяни отримують 3 очки за кожне завершене місто, що межує з полем. У старших виданнях ці правила відрізнялися. Еталон — правила фізичної копії команди. Якщо вони відрізняються, оновіть сценарії до генерації тестів.

### US-01. Створення кімнати

```gherkin
Feature: Створення кімнати без реєстрації

  Scenario: Успішне створення кімнати
    Given Олег відкрив головну сторінку Webcassonne
    When він вводить нікнейм "Олег" і натискає "Створити кімнату"
    Then відкривається лобі нової кімнати з унікальним посиланням
    And Олег позначений у списку гравців як організатор
    And від нього не вимагали email чи пароль

  Scenario: Порожній нікнейм
    Given Олег відкрив головну сторінку
    When він натискає "Створити кімнату" з порожнім полем нікнейму
    Then кімната не створюється
    And біля поля з'являється повідомлення "Введіть нікнейм"

  Scenario: Задовгий нікнейм
    Given Олег відкрив головну сторінку
    When він вводить нікнейм довжиною 21 символ
    Then кімната не створюється
    And з'являється повідомлення "Нікнейм — від 1 до 20 символів"
```

### US-02. Копіювання посилання-запрошення

```gherkin
Feature: Посилання-запрошення

  Scenario: Копіювання посилання
    Given Олег перебуває в лобі своєї кімнати
    When він натискає "Скопіювати посилання"
    Then посилання на кімнату потрапляє в буфер обміну
    And протягом 2 секунд показується підтвердження "Скопійовано"

  Scenario: Буфер обміну недоступний
    Given браузер Олега заборонив доступ до буфера обміну
    When він натискає "Скопіювати посилання"
    Then посилання показується в текстовому полі, виділене для ручного копіювання
```

### US-03. Вхід за посиланням

```gherkin
Feature: Приєднання до кімнати гостем

  Scenario: Успішне приєднання
```
