# ADR-0002. UI: React + TypeScript + Vite, поле на SVG

- **Статус:** прийнято
- **Дата:** 2026-10-28

## Контекст

UI має: форми (нікнейм), лобі з живим списком, ігрове поле, що росте в усі боки, з панорамуванням (US-08), підсвітку клітинок (US-11), вибір сегмента для міпла (US-13). Лише десктопний браузер. Команда знайома з React і TypeScript; досвіду з ігровими рушіями немає. Код значною мірою генерує ШІ, тому важливі поширеність стеку й строга типізація.

## Розглянуті варіанти

| Варіант | Плюси | Мінуси |
|---|---|---|
| **React + TS + Vite** | Команда знає; ШІ генерує добре; типи протоколу ловлять розбіжності з сервером; Vite — швидкий dev-сервер з проксі | Потрібен Node для збірки |
| Vanilla TS + Canvas | Мінімум залежностей | Форми й лобі доведеться писати вручну; Canvas ускладнює кліки по сегментах |
| Ігровий рушій (Phaser, PixiJS) | Зручні анімації | Анімації поза MVP; новий інструмент для команди; форми все одно в HTML |
| Svelte / Vue | Менше коду | Команда не знає; менше прикладів для ШІ |

Для поля: **SVG** замість Canvas — кожен тайл і сегмент є DOM-елементом з `onClick`, панорамування = зміна `viewBox`. На ~72 тайлах продуктивність не проблема.

## Рішення

React 19 + TypeScript (strict) + Vite. Поле — SVG без бібліотек. Маршрутизація і state-менеджер не додаються, поки не знадобляться (екранів 4, стан приходить знімком із сервера). Лінтер — oxlint (іде з шаблоном Vite).

## Наслідки

- Типи повідомлень у `web/src/api/types.ts` вручну дзеркалять `docs/api.md`.
- Додавання бібліотеки (router, state-менеджер, UI-кіт) — окреме рішення команди.
- Мобільна верстка поза MVP.
