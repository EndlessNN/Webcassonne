# ADR-0006. Тестовий стек: Vitest для клієнта і одна команда `npm test` з кореня

- **Статус:** прийнято
- **Дата:** 2026-11-26
- **Замінює:** рядок [ADR-0001](0001-repository-structure.md) «Кореневого `package.json` чи Makefile немає: дві команди з README достатньо».

## Контекст

Практика 6 вимагає, щоб усі автотести запускалися однією командою в терміналі. Зараз Go-тести запускаються `go -C server test ./...`, а клієнтських тестів немає. З інкрементом US-05–US-16 у `web/src/game/` з'явилася чиста клієнтська логіка (обертання US-10, підсвітка US-11, геометрія тайла), яку варто перевіряти без браузера. Команда працює на Linux і Windows; на Windows немає `make`. AGENTS.md §3 вимагає ADR для нової бібліотеки, а ADR-0001 забороняє кореневий `package.json`.

## Розглянуті варіанти

**Тести клієнта**

| Варіант | Плюси | Мінуси |
|---|---|---|
| **Vitest (середовище `node`)** | Бере конфігурацію й TS-трансформацію з наявного Vite; одна dev-залежність | Ще один пакет у `web/` |
| Jest | Поширений | Окреме налаштування TS (ts-jest або babel), дублює Vite |
| `node:test` | Без залежностей | Потребує окремої компіляції TS або експериментальних прапорців Node |
| Vitest + jsdom + Testing Library | Можна тестувати компоненти | Три залежності; вигляд і взаємодію однаково перевіряємо вручну |

**Одна команда**

| Варіант | Плюси | Мінуси |
|---|---|---|
| **Кореневий `package.json` лише зі `scripts`** | `npm test` однаково на Linux і Windows; Node уже потрібен для збірки UI | Відступ від ADR-0001 |
| Makefile (запасний варіант з ADR-0001) | Звично для Go | На Windows немає `make` |
| `test.sh` + `test.ps1` | Без npm | Два скрипти, які треба тримати однаковими |

## Рішення

- Клієнт: **Vitest** як dev-залежність у `web/`, середовище `node`, без jsdom і Testing Library. Тестуються лише чисті функції `web/src/game/`. Скрипт `"test": "vitest run"` у `web/package.json`.
- Корінь: **`package.json` лише зі `scripts`, без `dependencies` і `devDependencies`**: `test` (Go + web), `test:go`, `test:web`. Встановлювати в корені нічого не потрібно.
- Go: без змін — стандартний `testing`, `net/http/httptest`, наявний `github.com/coder/websocket`; без testify і gomock.
- E2E у браузері (Playwright тощо) не додаємо: інтерфейс перевіряється ручним smoke-чеклістом.

Решта ADR-0001 (монорепо `server/` + `web/` без монорепо-інструментів) лишається в силі.

## Наслідки

- Повний прогін: `npm test` з кореня; окремо `npm run test:go`, `npm run test:web`. Деталі — [testing-strategy.md](../testing-strategy.md).
- `npm test` у корені потребує `npm --prefix web install` для Vitest, так само як і збірка UI.
- Тестові файли `web/src/**/*.test.ts` потрапляють під `tsc -b` і oxlint разом з кодом.
- Компонентні тести або E2E, якщо знадобляться, — окремий ADR.
